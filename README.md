# Compiler Optimization Lab

**A Compiler Construction Course Research Project**

> **Core Idea:** Standard compilers blindly run **120+ cleanup checks** on every program, wasting most of their time on rules that make zero changes. **Compiler Optimization Lab** tests an AI-guided compiler that reads your program blueprint first, skips ~113 unnecessary checks, and applies only the **5–7 high-impact speedup tools** that matter—cutting optimization time by **~35–50%** while verifying **100% identical program output**.

---

## 1. The Problem & The AI Solution

### The Problem (Standard Compiler `-O2` / `-O3`)
Traditional optimizing compilers (such as Clang/LLVM) execute a rigid, one-size-fits-all checklist of **120+ optimization passes** in a fixed order for every file. On a typical algorithm, over **90% of those checks find nothing to improve**, yet the compiler still burns time analyzing loops, variables, and code structure for every pass.

### The AI Solution (Targeted Pass Selection)
Instead of running every rule blindly, an AI assistant inspects the unoptimized intermediate blueprint (**LLVM IR**), diagnoses the real performance bottlenecks (nested loops, repeated math, dead branches), and chooses a short, ordered sequence of **5 to 7 proven compiler speedup tools** (for example: `-mem2reg`, `-loop-rotate`, `-licm`, `-loop-unroll`, `-loop-vectorize`, `-instcombine`, `-dce`).

- **Faster Optimization:** Skips ~113 unneeded checks, speeding up optimization throughput by **35%–50%**.
- **Safe by Design:** Every AI suggestion is validated against an allowlist of safe compiler tools—the AI picks *which tools to run*, rather than rewriting raw code from scratch.
- **Verified Output:** Both compiled programs are executed multiple times and compared via output hash to guarantee **100% identical results**.

## 3. Canonical 6-Step Compiler Architecture

The lab models and visualizes the classic 6-step compiler structure (accessible via **"View 6 Steps"** on both compiler cards):

```text
                        +------------------------------+
                        |         Source Code          |
                        +--------------+---------------+
                                       |
                                       v
+----------------+      +----------------------------------+      +----------------+
|                | <--> | 1. Lexical Analysis (Scanner)    | ---> |                |
|                |      +----------------+-----------------+      |                |
|                |                       v                        |                |
|                | <--> | 2. Syntax Analysis (Parser)      | ---> |                |
|                |      +----------------+-----------------+      |                |
|                |                       v                        |                |
| Variable Table | <--> | 3. Semantic Analysis             | ---> | Error Checker  |
| (Names, Types  |      +----------------+-----------------+      | (Typos & Safe  |
|  & Scopes)     |                       v                        |  Tool Guard)   |
|                | <--> | 4. Intermediate Code Generation  | ---> |                |
|                |      +----------------+-----------------+      |                |
|                |                       v                        |                |
|                | <--> | 5. Code Optimization             | ---> |                |
|                |      |    [120+ Fixed vs 7 AI Tools]    |      |                |
|                |      +----------------+-----------------+      |                |
|                |                       v                        |                |
|                | <--> | 6. Target Code Generation        | ---> |                |
+----------------+      +----------------+-----------------+      +----------------+
                                         |
                                         v
                        +----------------------------------+
                        |      Final Working Program       |
                        +----------------------------------+
```

## 4. Benchmark Algorithms Included

1. **Grid Math — Matrix Multiplication (`128×128`)**: Triple-nested loops testing loop rotation, invariant code motion, and vectorization.
2. **Physics Sim — N-Body Particle Interaction**: Pairwise gravity math testing repeated expression cleanup and algebraic simplification.
3. **Prime Numbers — Sieve of Eratosthenes (`800K`)**: Memory stride loop testing branch simplification and induction variables.
4. **Audio Wave — Radix-2 FFT Butterfly**: Signal processing math testing instruction combining and loop unrolling.
5. **Quicksort Partitioning (`30K`)**: Recursive sorting testing tail-call cleanup and function inlining.
6. **Dead Code & Constant Folding**: Unreachable branches and constant math testing aggressive dead-code elimination (`-adce`, `-dce`).
7. **Custom Code**: Write or paste any C or C++ program directly in the editor to test live.

## 7. Deployment

### Deploying to Vercel
1. Push the full project source code (not just `README.md`) to your GitHub `main` branch.
2. Import the repository on [Vercel](https://vercel.com/new).
3. Vercel uses `vercel.json` automatically (`buildCommand: "vite build"`, `outputDirectory: "dist"`, `/api/*` routed to `/api`, SPA fallback to `/index.html`).
4. Add `GEMINI_API_KEY` in **Project Settings → Environment Variables**.
5. Click **Deploy**.

### Deploying with Docker (Full Native Clang/LLVM)
```bash
docker build -t compiler-optimization-lab .
docker run -p 3000:3000 -e GEMINI_API_KEY=your_key_here compiler-optimization-lab
```
